      01

      CLIP ranked complete captions. We now want to write an answer.

      The image must change the answer

      Keep the small grayscale grid from Vision I. The question is count ?. One grid contains two nonzero square blocks; removing its top-left block leaves one. A language model that ignores the image sees the same question in both cases. To answer differently, it must use the visual representations.

      This lesson develops the projected-prefix route used by models such as LLaVA, then compares it with the cross-attention route from Attention Part IV. These are documented architectures, not a claim about every commercial VLM.

      Keep the question fixed. The next-token distribution should depend on which image we supply.

      CLIP compares an image vector with complete text candidates.

      Here, a decoder predicts two, then blocks, then <eos>.

      $$p(y_t\mid I,\text{question},y_{<t})$$

      The image and known text are context. The unknown answer token is the prediction target.

      The image encoder is frozen. The connector and decoder were fitted to these two grids.

      One head, three decoder coordinates. No FFN, LayerNorm or dropout in this numerical worksheet.

      The purpose of fitting two pairs is to make image dependence testable. Success on those same pairs is not evidence that the toy understands arbitrary counts, natural photographs, or new questions. We inspect a fitted checkpoint, run generation, and then show one further update.

      02

      An image representation and a language representation can have different widths.

      Visual rows enter the decoder

      We reuse Vision I's patch projection, added positions, class token, and five-token attention calculation. The classifier used the updated class row. This time we retain the four updated patch rows and set the class row aside after the encoder. Call that matrix $G$. We reserve $V$ for attention values; $G$ is the encoder's visual output, not a value projection.

      $G$ has one row per patch. Each row already contains information mixed by the vision encoder.

      $$\ve{B}=\ve{G} W_{\rm bridge}+b_{\rm bridge}$$

      The same connector acts on every patch. Four rows remain four rows.

      visual_rows = vision_encoder(image)[:, 1:]
image_prefix = visual_rows @ W_bridge + b_bridge

      A new coordinate is a learned mixture of the incoming coordinates. It is not an extra position coordinate.

      $$\ve{E^{(0)}}=[\ve{B};E_{\rm tok}[\text{known text}]]+P$$

      Four visual rows plus three prompt rows give a $7\times3$ sequence.

      $P$ adds a same-width vector to each slot. Text uses a lookup; image rows come through the connector.

      A full-size example could have $196\times768$ visual rows and a $768\times4096$ connector, producing $196\times4096$ rows. These are example dimensions, not a universal VLM configuration. A plain linear map changes width, not token count. Pooling or a learned resampler can change token count as a separate operation.

      03

      Where do the decoder's keys and values come from?

      Two routes for visual information

      The connector supplies vectors, but an attention mask controls how they are used. Our toy puts image rows before the text and uses one prefix-attention block. Image rows can read all image rows but cannot read text. A text row can read every image row and only its current or earlier text rows. Preventing image rows from reading the answer also prevents a future-answer shortcut through image states in deeper blocks.

      The same mask is applied before softmax during teacher-forced training.

      Our numerical example uses the left route. Attention Part IV worked through the right route with an English source.

      $$\vq{Q}=\ve{E_{\rm text}}W_Q,\quad \vk{K}=\ve{G}W_K,\quad \vv{V}=\ve{G}W_V$$ $$\vd{\Delta E_{\rm text}}=\operatorname{softmax}\!\left(\frac{\vq{Q}\vk{K}^\top}{\sqrt{d_k}}\right)\vv{V}W_O$$

      A text query chooses a mixture of image values. $G$ and $E_{\rm text}$ need not have the same width; their projections produce compatible query/key widths.

      This is an architectural comparison, not a second hidden operation inside our prefix toy.

      Linear connector: $196\times768\;\to\;196\times4096$.

      Learned resampler: $n_r$ query rows read $196$ visual rows and produce $n_r$ output rows.

      $$\va{A_{\rm resample}}\in\mathbb R^{n_r\times196},\qquad \va{A_{\rm resample}}\vv{V}\in\mathbb R^{n_r\times d_v}$$

      Reducing token count saves later computation but can discard detail.

      Flamingo uses a visual resampler and cross-attention layers in a language model. BLIP-2 uses a learned query bridge. Those queries are learned query tokens, not the same thing as the last answer token's decoder query. Image tiling is another separate choice: it changes which image crops are encoded and may increase the visual token count. No single connector or training recipe describes all VLMs.

      04

      The last known token is the question mark, at sequence position 7.

      One image-conditioned prediction

      The prompt is <bos> count ?, preceded by four image rows. The decoder forms a query from the known question-mark row. It does not form a query from the answer two, which has not yet been generated. All seven available rows supply keys and values through the shared projection matrices.

      $\vq{q_7}=\ve{e_7}W_Q$. The learned projection defines which features this row matches.

      Q, K, V = E @ W_Q, E @ W_K, E @ W_V
q_last = Q[-1]

      Image keys come from projected image rows. Text keys come from text embeddings. Both use $W_K$ in this prefix decoder.

      $s_{7j}=\vq{q_7}\cdot\vk{k_j}/\sqrt{3}$, then $\va{\alpha_{7j}}=e^{s_{7j}}/\sum_r e^{s_{7r}}$.

      These weights mix input values. Here 0.000 is rounded, not masked.

      $\vv{m_7}=\sum_j\va{\alpha_{7j}}\vv{v_j}$, then $\vp{e_7'}=\ve{e_7}+\underbrace{\vv{m_7}W_O}_{\vd{\Delta e_7}}$.

      Small image weights can still matter: each weight multiplies a value vector, not just a token label.

      The head maps three updated coordinates to eight vocabulary logits. Vocabulary softmax gives the answer-token distribution.

      All projected values

      The numerical toy has the same width for embeddings, queries, keys and values, but their roles and projection matrices differ. Equal shape does not mean equal numbers or interchangeable meaning. The frozen image encoder's width is two; only its connector output has the decoder width of three.

      The displayed weight 0.000 is a small positive number rounded to three decimals, not a masked entry. This query puts most of its weight on text, but that alone does not establish that the image is ignored. The value vectors, output projection and prediction head also matter. The next section tests image dependence by changing the pixels while holding the question and parameters fixed.

      05

      Generation supplies its own next input.

      Generate from the last known position

      We use greedy decoding for this worked trace. At each step, choose the most probable token and append it. The model parameters do not change during generation. The image remains the same, while the new last text row supplies the query for the next prediction. These choices are actual outputs of the saved toy, not a scripted animation of the desired answer.

      Only the image and question are inputs. Choose the first answer token from the last row's distribution.

      The sequence has grown. The new last row supplies a new query through the same $W_Q$.

      next_id = logits[-1].argmax()
prefix = torch.cat([prefix, next_id[None]])

      Both cases use the same learned parameters and <bos> count ? prompt.

      The switch is a conditioning check, not a generalization test: both grids were in the two-pair training set. A frozen vision encoder can be run once per image. Cache the visual states and, in a multi-layer implementation, eligible key/value projections. Reusing context does not mean reusing the last text query unchanged.

      06

      The response supplies targets; the mask keeps them out of earlier predictions.

      Train on the observed answer

      Teacher forcing supplies the correct earlier answer tokens. The first prediction uses the question-mark row, the second uses the supplied two row, and the third uses blocks. Loss is measured only on those three answer predictions. Ignoring an image or question position in the loss does not stop gradients through that position: its representation can influence an answer row.

      The image and question are context. They do not receive vocabulary prediction targets in this response-only objective.

      loss = F.cross_entropy(logits[answer_rows], answer_ids)

      Compute with full precision. The tables round to three decimals.

      Backpropagation reaches both attention weights and values. The optimizer changes learned parameters, not cached $\vq{Q},\vk{K},\vv{V}$.

      optimizer.zero_grad()
loss.backward()
optimizer.step()

      This step uses only the two-block grid. Its loss falls, but the one-block loss rises.

      The one-block image now gets the wrong answer. Lower training loss on one example is not evidence of broader improvement.

      Train on representative batches and check held-out images. Here we deliberately keep the failed update visible.

      Freezing parameters does not mean cutting the gradient path through a frozen language model to a trainable connector.

      The recorded warm-up fits two pairs with Adam. The displayed further step uses SGD at learning rate 0.02 so the parameter update is easy to state. The reference generator checks every trainable scalar by finite differences; students use autograd rather than deriving those gradients by hand.

      LLaVA's original staged recipe first fits a connector with pretrained components frozen, then instruction-tunes with a different trainable set. This is a useful example, not a mandatory sequence of four stages for every VLM. Preference optimization can follow supervised training, but preference labels do not by themselves prove visual correctness. LoRA, full fine-tuning, frozen encoders, and joint training are choices whose value depends on data, domain, memory, and validation results.

      07

      A plausible sentence can still contradict the image.

      Check grounding, not just fluency

      The earlier article's thermal example raises a useful evidence question: which information is actually available in the displayed pixels? A false-colour rendering without its scale can hide the mapping to physical temperature. A model cannot recover a unique absolute temperature from information that was removed. A visible calibrated legend or radiometric metadata changes what can be inferred.

      Keep the question fixed and change only the image. Does the answer track the change?

      Test new layouts, brightnesses and distractors. Include images with zero blocks and questions whose answer is unavailable.

      Our two-pair toy has not passed these tests. Its success demonstrates the computation, not a general ability to count.

      Without the scale or calibration data, an absolute-temperature answer is underdetermined.

      1. Locate the region or measurement requested.
      2. Read calibrated sensor data with an appropriate tool.
      3. Report the measurement, units and assumptions with the answer.

      Tools add evidence. Their calibration, coordinate mapping and failure cases still need checking.

      Reading and implementation sources

      ViT supplies the patch-sequence architecture; LLaVA is the projected-prefix example; Flamingo and BLIP-2 show different visual-language interfaces. The adaptation preserves the questions about connectors, training choices, retrieval versus generation, and sensor calibration from the earlier VLM article. Its numerical trainer is replaced here by a separately checked toy.

      For a real evaluation, separate retrieval ranking, answer correctness, visual grounding, and abstention on unavailable information. Report the dataset split, prompt and preprocessing, and inspect failures. A fluent answer or a high softmax probability is not a substitute for that evidence.
