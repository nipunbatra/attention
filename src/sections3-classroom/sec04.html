Multi-head attention · a worked continuation

TinyStories: the multi-head model, training and generation

The ID for “found” selects one row of 64 learned numbers. All occurrences share that token row. B counts examples, not heads.

token_rows = token_embedding(X)

The PAD token row is initialized to zero and receives no embedding-lookup gradient here, using padding_idx=0. BOS and UNK can learn when used in inputs. EOS is a target rather than an input in these windows, so its input row receives no task gradient. The separate classifier learns an EOS output score. Padding still needs an attention mask.

Use positions 0–63 within each padded or cropped window. Adding keeps each row 64 numbers wide. Both tables learn from the prediction loss.

positions = torch.arange(X.shape[1], device=X.device)
E = token_rows + position_embedding(positions)[None]

Every head reads the full input row through learned projections. Split the projected coordinates into four groups of 16.

Q, K, V = (split_heads(layer(E)) for layer in (W_Q, W_K, W_V))

For the two examples, each projected tensor is [2,4,64,16]: examples, heads, token slots, coordinates per head. Packed W_Q, W_K and W_V each map 64 input coordinates to 64 output coordinates.

For “BOS lily found”, follow the query at “found”. Its scores compare that receiver with the keys of the available source tokens.

scores = (Q @ K.transpose(-2, -1)) / math.sqrt(16)

At “found”, allow BOS, lily and found. PAD and future slots receive zero weight. Each real receiver’s source weights sum to one.

This is the full causal teaching view for real receiver rows. The implementation keeps PAD-only receiver rows numerically defined; they do not feed the loss. The saved training and browser forward path computes only the final receiver’s query, since this task predicts one next token per window. It produces the same final logits with smaller [B,4,1,64] weight tensors.

A weight scales a complete 16-number value row. Add those weighted rows to make one message per receiver, per head.

messages = A @ V

Joining four 16-coordinate messages restores width 64. W_O learns how to combine them; the residual adds this update to the original E.

joined = messages.transpose(1, 2).reshape(B, 64, 64)
updated = E + W_O(joined)

“BOS lily found” → target a. “BOS lily found a” → target red. The model supplies scores; the story supplies the answers.

logits = vocab_head(relu(hidden_layer(updated[:, -1])))
loss = cross_entropy(logits, y)  # raw logits, observed next-token IDs

Repeat over batches. The loss trains token rows, position rows, all four heads, W_O and the prediction MLP. Validation selects a checkpoint; test measures that frozen choice.

optimizer.zero_grad()
loss.backward()
optimizer.step()

We do not assign head-specific targets such as “setting” or “person”. All heads learn through the same next-token task. These are one-block teaching models, not a full stack of normalized Transformer blocks.

Use the training vocabulary and prepend BOS. Do not append EOS to an unfinished prompt. Load the chosen checkpoint and keep its parameters fixed.

Left-pad this short prefix with 61 PAD IDs. After the history grows past 64 tokens, retain its last 64 IDs. There is no observed next-token target during free generation.

Greedy decoding takes the highest score; sampling draws from the probability distribution. Exclude PAD, BOS and UNK as outputs. EOS can stop the story.

Attention softmax chooses source positions. Vocabulary softmax supplies next-token probabilities. Cross-entropy uses raw logits during training; we do not first apply this generation softmax before that loss.

Keep generating until EOS or a token limit. Training used observed previous words; generation now feeds back the model’s own choices.

“a” here is an illustrative choice, not a claimed checkpoint output. The saved continuations later show the actual outputs. An early mistake can alter every later input. The weights stay fixed throughout generation.
