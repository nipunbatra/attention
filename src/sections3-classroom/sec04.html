One quick pass through the four-head model

Now use 64 slots, width 64 and four heads of width 16. B counts examples: two above, 512 per training batch.

E = token_embedding(X) + position_embedding(positions)
Q, K, V = (split_heads(layer(E)) for layer in (W_Q, W_K, W_V))

The four heads form four different attention patterns. Targets never enter this calculation.

This is the full causal teaching view for real receiver rows. The implementation keeps PAD-only receiver rows numerically defined; they do not feed the loss. The saved training and browser forward path computes only the final receiver’s query, since this task predicts one next token per window. It produces the same final logits with smaller [B,4,1,64] weight tensors.

Each head sends its own message. Joining four 16-coordinate messages restores width 64.

messages = A @ V
joined = messages.transpose(1, 2).reshape(B, 64, 64)
updated = E + W_O(joined)

“BOS lily found” → target a. “BOS lily found a” → target red. The model supplies scores; the story supplies the answers.

logits = vocab_head(relu(hidden_layer(updated[:, -1])))
loss = cross_entropy(logits, y)  # raw logits, observed next-token IDs

Token rows, position rows, all heads, the output projection and the prediction MLP learn together.

optimizer.zero_grad()
loss.backward()
optimizer.step()

We do not assign head-specific targets such as “setting” or “person”. All heads learn through the same next-token task. These are one-block teaching models, not a full stack of normalized Transformer blocks.

Training changes the weights. Generation keeps the weights fixed and grows the prefix.

The app excludes PAD, BOS and UNK as generated outputs; EOS may end the story. The same tokenizer and vocabulary are used for training and generation. Attention softmax chooses source positions; vocabulary softmax supplies next-token probabilities.
