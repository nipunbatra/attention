Two patches with the same pixels get the same row. The question asks about the right half, so a row must know where it came from.

Position and a row for the answer

Two things are still missing. The first is position. Patches 2 and 4 contain the same pixels and therefore the same row, yet one sits in the left half and one in the right, and our question is about the right half. As in Part 2, we add a position row of the same width; because the toy's last two axes are named row and col, the position row simply fills them. The second missing piece is a row that will carry the answer. An image has no last patch, so we add one extra row with no pixels, CLS, and let it read all sixteen. The last frame swaps two patches to show what position buys.

Two patches of scene A with identical content rows

The projection cannot tell these two apart. Their place in the grid can, and the model has to be told it.

$$p_j = \bigl(0,\ 0,\ \tfrac{\text{row}}{3},\ \tfrac{\text{col}}{3}\bigr)$$

Row and column of the patch grid, counted from 0, so both run from 0 to 1.

$\ve{e_0} = c + p_0$: a fixed start row plus a position of its own

CLS is the row that will answer. It starts the same for every scene and knows nothing yet; attention will bring the patches to it.

Why are the last two rows exactly equal? Without positions, the swap only reorders the sixteen patch rows. Every key and value is still there, the softmax sums over all of them in any order, and CLS receives the same weighted sum. Attention is permutation invariant for CLS unless the rows themselves carry their place. The position row is what makes “on the right” visible to the layer.

Seventeen rows on four named axes: sixteen patches that know their place, and one CLS row that knows nothing yet. The next section gives CLS a query and every row a key, and lets CLS decide where to read.
