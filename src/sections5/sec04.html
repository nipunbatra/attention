Let CLS choose how much to read

We want the collection row to depend on the image. The query is the receiving row’s matching request; each source key is a description it can match. These are vectors, not written questions. In this starting model, CLS’s query gives equal positive weight to both key coordinates, so it favors keys with a larger sum. A trained model can learn different combinations.

This query comes from CLS, not the label. It will compare both coordinates of each source key.

Patch 4’s key comes from its own positioned row, $e_4=(5,5)$. It describes when this source should be read by CLS’s query.

The dot product favors patch 4’s large key coordinates. This starting query has not learned to count blocks yet.

More coordinates tend to widen the spread of dot products. Dividing by $\sqrt{d_k}$ controls that spread before softmax. Here $d_k=2$.

The largest score still belongs to patch 4. Dividing by $\sqrt2$ makes its advantage less extreme.

Why the square root, more precisely?

If corresponding query and key coordinates are independent, roughly zero-mean, and unit-variance, the variance of their summed products grows like $d_k$. Dividing by $\sqrt{d_k}$ keeps the score variance around 1 under those assumptions. This is a scale-control argument, not a guarantee for every learned vector. See the scaled dot-product discussion in Attention Is All You Need.

Our starting $W_Q$ and $W_K$ are equal for easy arithmetic; training stores and updates them separately. The CLS query is not yet image-dependent in this first layer. Its matches are image-dependent because the source keys come from each image. In later layers, an already-contextual CLS row can also produce an image-dependent query.
