Follow four pixels into two features, one coordinate at a time.

Make one embedding from each patch

A Transformer expects a sequence of equal-width rows. We could flatten the whole image into one long row, but then attention would have no separate regions to relate. We could use one row per pixel, but photographs would produce very long sequences. Patches choose an intermediate scale. Here a 2×2 patch gives four raw pixel values.

Number patches left to right, then top to bottom. Keep this order throughout the calculation.

$N=(4/2)\times(4/2)=4\text{ patches}$

Flattening only rearranges. It has no learned weights and does not mix the four pixels.

Give each patch a row whose width we choose: here, $d_{\mathrm{model}}=2$.

$\underbrace{r_j}_{1\times4}\;\underbrace{W_{\mathrm{patch}}}_{4\times2}+\underbrace{b_{\mathrm{patch}}}_{1\times2}=\underbrace{e_j^{\mathrm{patch}}}_{1\times2}$

Each output coordinate can combine several pixels. Training will change those combinations to help with the image task.

This is the image equivalent of making a token embedding. The patch’s actual pixels determine its row.

At these starting weights, coordinate 1 adds the left column of the patch. The bias is zero.

Coordinate 2 adds the right column. Patch 4’s embedding is now $e_4^{\mathrm{patch}}=(4,4)$.

Only the left-column sum changes: $(4,4)\to(3,4)$. The right-column sum stays 4.

patch_embeddings = raw_patches @ W_patch + b_patch
# [4, 4] @ [4, 2] + [2] → [4, 2]

Extract the rows in PyTorch

rows = F.unfold(image, kernel_size=2, stride=2).transpose(1, 2)
patch_embeddings = rows @ W_patch + b_patch

Here image has shape [batch, 1, 4, 4]. The rows have shape [batch, 4 patches, 4 pixels]. A convolution with kernel size and stride equal to the patch side can perform this same shared patch projection.

What if the patch size changes?

These controls inspect how pixels are grouped. A new patch width needs a correspondingly sized projection; they do not silently run the fixed 4×2 weight matrix on a different-width row.
