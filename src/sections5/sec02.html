A patch is a small rectangle of pixels, not an object detector.

Make one vector per patch

Split the image into nonoverlapping 2×2 patches. Number them left to right across the top row, then across the bottom row. Within each patch, use the same order to flatten its four pixel values. Flattening changes the arrangement of the numbers, not their values. A patch boundary need not follow an object boundary.

Each raw row $r_j$ has shape $1\times4$. Stacking the four patches gives $R\in\mathbb R^{4\times4}$.

# image: [batch=1, channels=1, height=4, width=4]
R = image.unfold(2, 2, 2).unfold(3, 2, 2)
R = R.permute(0, 2, 3, 1, 4, 5).reshape(1, 4, 4)

$\ve{e_j^{\mathrm{patch}}}=r_jW_{\mathrm{patch}}$

For patch 1:

$(1,1,1,1)W_{\mathrm{patch}}=(2,2)$

Coordinate 1 adds pixels 1 and 3. Coordinate 2 adds pixels 2 and 4.

These weights are chosen for arithmetic. In a trained model, the projection and its optional bias are learned.

# R: [1, 4, 4]; W_patch: [4, 2]
patch_rows = R @ W_patch + b_patch  # [1, 4, 2]

Four different patch inputs, one shared $W_{\mathrm{patch}}$. The two zero patches get the same embedding before position is added.

Our $4\times2$ projection is for 2×2 grayscale patches. Other patch sizes need a different projection shape.

For height $H$, width $W$, channels $C$, and patch side $P$ that divides both spatial dimensions, there are $N=HW/P^2$ patches. A flattened patch has $P^2C$ numbers, so $W_{\mathrm{patch}}$ has shape $P^2C\times d_{\mathrm{model}}$. RGB changes the raw width through $C=3$; it does not force the learned embedding to have three coordinates.
