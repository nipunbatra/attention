01

Attention needs a sequence of rows. A photograph is a grid of pixels. How many rows should it become?

Why patches?

The whole page runs on one small model that you can check by hand: an 8×8 grayscale scene, sixteen 2×2 patches, one extra CLS row, one attention head with two matching axes, and a class head with two answers. Its axes have names because we chose the patch projection and the position rows so that the names are true, and we never trained those two. Everything else (the four attention matrices and the class head) was trained on two scenes.

  • It can show every number of a forward pass, what CLS reads before and after training, and how one update turns a wrong answer into a right one.
  • It cannot show what a real Vision Transformer learns: two training scenes fit a rule, and scene C in section 8 is the only test of that rule. A real ViT has LayerNorm, a feed-forward sublayer, several heads and a dozen blocks; section 10 adds those shapes without pretending we computed them.
  • The photograph in section 2 sets the task. The model never sees it; every later picture is the scene it computes on.

Part 2 gave every word a row and let the rows exchange information through attention. An image has no words. It has pixels, and a photograph has a lot of them: 224×224 is a small input for a vision model and already 50,176 pixels. This section asks the first design question of a Vision Transformer, how many rows an image should become, and answers it with the slider below. Move the patch side and watch two numbers: the rows that go into attention, and the scores one head has to compute, which grow with the square of the row count. The rest of the page then follows one tiny image through the same chain as Part 2.

A 224×224 image, cut into square patches

One row per pixel gives attention rows and scores per head for a single image. Each row would describe one pixel, which on its own says almost nothing.

One row per image gives attention one row. There is nothing to relate, and the layer has no work to do.

A patch of pixels gives rows. Each row describes a piece of the image large enough to carry some structure, and the score matrix has entries.

A patch is a piece of the input, chosen by a grid. It is not an object, and the model does not know where the objects are when it cuts.

The pipeline of Part 2, unchanged after the first arrow

Only the way rows are made changes. Everything from $\ve{E}$ to $\vp{E'}$ is the operation of Part 2, run on seventeen rows instead of ten.
Two changes matter most: a projection instead of a lookup, and a new row, CLS, because an image has no last token to predict from.

A Vision Transformer decides how many rows an image becomes by choosing a patch side. From there on, the chain is the one we know. The next section picks the scene we will compute on, and the question we will ask about it.
