Attention needs rows of numbers. An image can supply them too.

An image as input

In the attention series, a token lookup supplied each input row. The rest of the computation operated on numbers: queries chose a mixture of values, and a residual addition updated each row. We can keep that machinery for images. First we need a way to turn pixels into rows. This part follows one 4×4 grayscale image through that process and a classification head.

Pixel values: $0$ is dark, $1$ is medium, and $2$ is bright. This is a synthetic grayscale image with one channel.

Class A and class B are worksheet outputs. Our hand-chosen weights have not learned visual categories.

Text input

A token ID selects a row from an embedding table.

$\text{token ID}\to\ve{e_i}$

Image input

A patch of pixels is flattened and multiplied by a learned matrix.

$\text{patch pixels}\to\ve{e_j^{\mathrm{patch}}}$

An image patch has no word ID to look up. The patch projection creates its embedding from its pixel values.

Our worksheet uses two-number rows and one attention head. Every displayed number comes from the same forward pass.

We leave LayerNorm and the feed-forward sublayer out of this numerical example. Later we put them back into the architecture diagram.

All calculations run locally in the page. There is no model download and no hidden image classifier behind the diagrams. The larger question is how the same construction scales from a few patches to a photograph; we will separate that shape calculation from the small numerical example.
