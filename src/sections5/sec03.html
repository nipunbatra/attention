The patch contents are ready. What else does the model need?

Keep the layout; make room for an image answer

Two pieces remain before attention. We add a position vector so that a row contains information about its location as well as its pixels. We also introduce an extra receiving row, CLS, because our output is one label for the whole image. Position and CLS are learned parameters; they are not extra pixels or supplied answers.

Which side has the brightest block? Counting can ignore layout; this question cannot. Position additions preserve the distinction.

$e_j=e_j^{\mathrm{patch}}+p_j\qquad(1\times2)+(1\times2)=(1\times2)$

The two blank patches have the same pixels. Their different position additions let later computations distinguish their slots.

Text used the last known word’s row. An image has no natural last token to represent the scene.

Averaging the final patch rows is one option. We will use a separate collection row.

$e_0=c+p_0=(1,1)+(0,0)$. Both images start with this same CLS row; reading their patches can give different updated rows.

From here, $e_j$ means the current row, including its position addition. Row 0 is CLS; rows 1–4 are the four patches.

E = torch.cat([cls[None, :], patch_embeddings], dim=0)
E = E + positions               # [5, 2]

The starting CLS parameter is shared. The patch rows supply the image-specific information that CLS will read.

A check on why positions matter

Without position additions, permuting the four patch rows leaves the CLS output unchanged in this model. The patch outputs permute in the same way as the inputs. This is permutation equivariance, together with an invariant CLS readout. Adding different slot vectors lets the computation depend on which patch occupies which slot. The original ViT learns a full-width position vector for each slot; it does not append a special scalar “position dimension.”
