A word became a row by lookup. A patch becomes a row by projection, and we can name what the row measures.

Every patch becomes a row with named axes

In Part 2 a token's row came from a table: the token ID picked a stored row. A patch has no ID, only four pixel values, and its row is a linear combination of them, $r_j W_{\text{patch}}$. We chose $W_{\text{patch}}$ by hand so that the first two output coordinates have honest names: brightness is the mean of the four pixels, contrast is the left column minus the right. The last two coordinates, row and col, stay zero here; the next section fills them with position. Work one patch by hand, then look at all sixteen rows as points in the brightness and contrast plane: the plane already separates mugs, book, plant and table.

The row of patch $j$ is a projection of its pixels plus a position row, which section 4 adds:

$$\underbrace{\ve{e_j}}_{1\times4} = \underbrace{r_j}_{1\times4}\,\underbrace{W_{\text{patch}}}_{4\times4} + \underbrace{p_j}_{1\times4}$$
This is the image version of the token lookup. The numbers come from the pixels, not from an ID, so two patches with the same pixels get the same row.
