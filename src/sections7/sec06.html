The candidate text supplies the classifier

Keep both encoders fixed. For each candidate class, write a description and encode it into a unit text vector. Those text vectors are the classifier's weight rows: the image vector scores each candidate with a dot product. Changing the candidate list changes the readout without changing the learned encoders.

For pretrained CLIP, this is zero-shot classification when no training on labeled examples from the target task is used. Our tiny checkpoint has already seen the three displayed images and descriptions, so its scores illustrate the inference mechanism rather than demonstrating zero-shot transfer.

Prompts are part of the evaluation

A class name can be ambiguous: crane may mean a bird or a machine. A description can specify the intended sense. The CLIP paper evaluates prompt templates such as a photo of a {label} and averages normalized text embeddings across templates, then normalizes the result. Prompt choice can help, but no wording guarantees an improvement on every dataset. See the paper's prompt experiments.

The current toy template adds word rows according to its bag-of-words rule. Template-only words such as grid retain their hand-chosen starting rows because the training captions do not contain them. The toy cannot show the full contextual behavior of a text Transformer. In a real deployment, report the candidate set and prompt policy alongside accuracy, and evaluate on held-out task data.
