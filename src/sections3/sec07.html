Why we are here: one head produces one routing pattern, while a token may need several relations at the same time.

Multiple heads

Consider "Priya opened the notebook; she smiled." When the row for she gathers context, one useful pattern links it to Priya, another retrieves the earlier event, and a third notices nearby structure. Multi-head attention gives each head its own query, key, and value projections. Every head reads the full input representation through those matrices. It does not receive a separate slice of the embedding. Each head returns a smaller projected message, the messages are concatenated by columns, and $W_O$ combines them. $$\vq{Q^{(h)}}=\ve{E}W_Q^{(h)},\qquad \vk{K^{(h)}}=\ve{E}W_K^{(h)}$$ $$\vv{V^{(h)}}=\ve{E}W_V^{(h)}$$
$$\va{A^{(h)}}=\operatorname{softmax}_{\text{row}}\!\left(\frac{\vq{Q^{(h)}}\vk{K^{(h)}}^\top}{\sqrt{d_k}}+M\right)$$

The same causal mask $M$ blocks future sources in every head.

$$H^{(h)}=\va{A^{(h)}}\vv{V^{(h)}}$$

Each head returns one message row per input token.

$$H=\operatorname{Concat}_{\text{columns}}(H^{(1)},\ldots,H^{(n_h)}),\qquad \vd{\Delta E}=HW_O$$
