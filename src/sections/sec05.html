A detour through search: query, key, value

Think of searching a video site. For each item, we need to decide whether it matches our request and what information to return. In this example, each video has a key for matching and a value for returning. The first table puts the query above six keys so you can compare their coordinates. Each score on the right is a dot product. Switch to the overfitting question and see which item now scores highest. Its key helps us choose it; its value is what we receive.

A user asks a video site a question. That request is the query.

What are we looking for?

Two separate jobs: decide which items match, then decide what information to return.

Query

The query describes the request. Each item's key describes when it is a useful match.

Multiply matching coordinates, then add: $s_j=\vq{q}\cdot\vk{k_j}$.

For this matching step, the site uses only the dot product between the query and each key.

$$s_j = \vq{q}\cdot \vk{k_j}$$

$\vq{q}$ = query representation, $\vk{k_j}$ = key of item $j$, $\vv{v_j}$ = value of item $j$.

QWhat am I looking for?the query, formed by the searcher
KWhen should you retrieve me?the key, one per item, used for matching
VWhat information do I send?the value, one per item, the payload

Each video's value: the information returned

The key chose the item. The value supplies the information returned.

A high score says retrieve Backpropagation, but what arrives is its value, not its key. For this toy lookup, take the highest-scoring item. Real search engines usually rank several results; attention instead mixes values using soft weights.

Only the query and key determine the match score. Once we choose an item, we retrieve its value.
