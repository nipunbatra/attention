Why we are here: the obvious fix, handing the model the last w tokens, and why it is not enough.

Baseline: a fixed window of w tokens

The natural fix is to hand the model more tokens: concatenate the last $w$ representations into one long row and let a bigger matrix read it. The first widget sketches that as a network: the input column is the window, and the first layer's input width grows with the window. Drag the second slider and watch which tokens sit inside the window and how the input grows by five numbers per token. Set $w$ to 3 and river falls outside. Set it to 10 and every token is in, but only because this sentence is short. The included embeddings still carry content: a network can learn to treat river differently from the. The limitation is the fixed input width and hard boundary, not an inability to use the words. The sentence to remember: a window decides by position what to include, and we want to decide by content.

Why not simply hand the model the last $w$ tokens? Their rows feed a fixed network: a first layer that reads all $w$ rows at once, a hidden layer, and one output per vocabulary word.

A fixed window feeds a fixed network

Sketch, not the toy's arithmetic: the hidden width $h$ is a stated choice, the outputs are the toy vocabulary with the answer for context A marked. Drag the slider or press the arrow key.

Change the window, change the network. The window size is baked into the shape of the first layer before any word is read.

Concatenate the previous $w$ token representations into one long vector and predict from that. $w$ denotes the window width; we reserve $K$ for the matrix of attention keys later.

Choose the window: which tokens reach the prediction?

$$c_t = [\ve{e_{t-w+1}};\,\ve{e_{t-w+2}};\,\ldots;\,\ve{e_t}], \qquad p(x_{t+1}\mid x_{\le t}) = \operatorname{softmax}(c_t W + b)$$

$W$ is a new, larger matrix, not section 02's $W_{\text{vocab}}$: it has $w d_{\text{model}} \times |\mathcal V|$ entries.

1The boundary is hard

Anything before the previous $w$ tokens is unavailable. It is not down-weighted; it is absent.

2Slots are fixed by position

The model receives all $w$ representations, each in a slot set by its distance from the end. The network can respond differently to different embeddings in a slot. What remains fixed is the number of slots and which positions are supplied; there is no explicit query-dependent retrieval step here.

3Relevant context changes dynamically

For different predictions, different previous tokens matter. Two prediction slots in the same sentence. Outlines are illustrative (they mark the tokens the later toy mechanism gives the largest weights for these queries)

Look at the outlined tokens: a different set, at different distances from the slot. A sufficiently large window includes both sets; it still has one fixed boundary.

4Increasing w does not remove the problem

A larger $w$ adds input dimensions and parameters in $W$, and may include tokens that are less useful for this prediction. The cut-off is still fixed.

Could we dynamically retrieve only the information that is useful right now?

Keep in mind: a fixed window chooses tokens by where they are, never by what they say. The rest of the page builds a mechanism that chooses by content.
