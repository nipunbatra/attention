Why we are here: the obvious fix, handing the model the last K tokens, and why it is not enough.

Baseline: a fixed window of K tokens

The natural fix is to hand the model more tokens: concatenate the last $K$ representations into one long row and let a bigger matrix read it. The first widget sketches that as a network: the input column is the window, and the first layer has to be as wide as the window. Drag the second slider and watch two things, which tokens sit inside the window, and how the input grows by four numbers per token. Set $K$ to 3 and river falls outside. Set it to 10 and every token is in, but only because this sentence is short. Each row also lands in a slot decided by its position, so $W$ cannot treat river differently from the. The sentence to remember: a window decides by position what to include, and we want to decide by content.

Why not simply hand the model the last $w$ tokens? Their rows feed a fixed network: a first layer that reads all $w$ rows at once, a hidden layer, and one output per vocabulary word.

A fixed window feeds a fixed network

Sketch, not the toy's arithmetic: the hidden width $h$ is a stated choice, the outputs are the toy vocabulary with the answer for context A marked. Drag the slider or press the arrow key.

Change the window, change the network. The window size is baked into the shape of the first layer before any word is read.

Concatenate the previous $K$ token representations into one long vector and predict from that. $K$ here is the window size, not the key chip in the strip above.

Choose the window: which tokens reach the prediction?

$$c_t = [\ve{e_{t-K+1}};\,\ve{e_{t-K+2}};\,\ldots;\,\ve{e_t}], \qquad p(x_{t+1}\mid x_{\le t}) = \operatorname{softmax}(W c_t + b)$$

$W$ is a new, larger matrix, not section 02's $W_{\text{vocab}}$: it has $|\mathcal V| \times K d_{\text{model}}$ entries.

1The boundary is hard

Anything before the previous $K$ tokens is unavailable. It is not down-weighted; it is absent.

2Slots are fixed by position

The model receives all $K$ representations, each in a slot set by its distance from the end. $W$ can learn to weight a slot, but that weight is fixed before the words are read: the same slot weights apply whether the slot holds river or the.

3Relevant context changes dynamically

For different predictions, different previous tokens matter. Two prediction slots in the same sentence. Outlines are illustrative (they mark the tokens that the mechanism built later on this page reads most)

Look at the outlined tokens: a different set, at different distances from the slot. No fixed window fits both.

4Increasing K does not remove the problem

A larger $K$ adds input dimensions and parameters in $W$, and it includes more irrelevant tokens. The cut-off is still fixed.

Could we dynamically retrieve only the information that is useful right now?

Keep in mind: a fixed window chooses tokens by where they are, never by what they say. The rest of the page builds a mechanism that chooses by content.
