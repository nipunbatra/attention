A vector for position $i$.

Starting row: $e_i^{(0)}$

Their sum, before any contextual update.

$$\htmlClass{start-row}{e_i^{(0)}}=\htmlClass{start-token}{E_{\text{tok}}[t_i]}+\htmlClass{start-position}{p_i}$$

The superscript $(0)$ means “before any contextual update.” The position cue uses the existing coordinates. At position 1, the pattern is $[0,1,0,1]$ because the sine of zero is zero and the cosine of zero is one.

For readers who want the calculation: let pos = i - 1, so the first displayed position has index zero. With four coordinates, the original Transformer’s positional encoding gives p = [sin(pos), cos(pos), sin(pos / 100), cos(pos / 100)]. The pairs vary at different frequencies. The position values here come from that formula, while the word values are chosen just to show the addition.

Positional vectors can also be learned from data. Addition is one way to supply position information, not a requirement for every Transformer architecture. We’ll return to the design choices later.

The bank example uses five hand-chosen coordinates, different from the four-coordinate sinusoidal illustration above. Names such as water and finance let us follow the arithmetic. Real learned coordinates need not have these meanings.

The bank model’s matching, message, and prediction calculations ignore coordinate 5. That coordinate stores a position offset, labelled “pos” in its tables, but it has zero projection weights. The changing bank predictions demonstrate content gathering, not sensitivity to word order.

One sentence, ten token rows. The blank has no row yet.

We call the number of input tokens $T$. Here we have ten tokens, even though some words repeat. The symbol $d_{\text{model}}$ counts the numbers used to represent each token. In our bank toy, that count is five. So the sentence matrix $\ve{E}$ has ten rows and five columns.

Lowercase $\ve{e_i}$ means the row for token position $i$. For example, $\ve{e_6}=[3.0,0.0,0.0,0.0,0.6]$ is the row for river. Before any contextual update, $e_i=e_i^{(0)}$. Stacking the rows gives $E=[e_1;\ldots;e_T]$, with shape $T\times d_{\text{model}}$. The table shows the starting values from our hand-chosen bank model.

$E_{\text{tok}}$ is the vocabulary lookup table shared across sentences. $E$ holds the rows for this particular input. Contextual updates change the rows of $E$ during the forward pass. Training can change the stored lookup table.

The model works with a row of numbers per token. We judge its prediction by the probability it assigns to the correct next word, so those rows need to carry the relevant context.
