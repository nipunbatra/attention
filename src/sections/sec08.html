Why we are here: one query, seven records. Attention happens in two separate phases: deciding where to read, then reading.

Two jobs: choose weights, then mix values

Attention is easier to trust once you see that it is two separate jobs. Phase A uses only queries and keys: it scores every earlier token and turns the scores into weights that sum to one. Phase B uses only values: each token sends its value, scaled by its weight, and the scaled values are added.

Run phase A, then click a key in the picture to see its dot product written out, axis by axis. Then run phase B and read the sum, one coordinate per line. Switch between the value rows and the $\va{\alpha}\vv{v}$ products. The sentence to remember: keys decide where to read, values decide what is read.

Take “bank” (token 7) as the query in The fisherman sat beside the river bank. First choose where to read. Then mix what those sources send.

Phase A · read routing

$\vq{q_{7}}$ against every key $\vk{k_j}$: one score per row, then softmax turns the scores into weights $\va{\alpha_{7j}}$

$$\va{\alpha_{ij}} = \operatorname{softmax}_j\!\left(s_{ij}\right), \qquad s_{ij} = \frac{\vq{q_i}\cdot\vk{k_j}}{\sqrt{d_k}}$$

Dividing by the constant $\sqrt{d_k}$ only rescales the scores (why, in section 12). Only the query and the keys took part. No representation has been updated.

scores = (q_bank @ K.T) / math.sqrt(K.shape[-1])
alpha = scores.softmax(dim=-1)  # seven source positions
Q and K determine where bank reads. The values have not entered this calculation.

A key supplies a possible match. Its corresponding value supplies the information to mix.
Phase B · message passing

Each token $j$ sends its value $\vv{v_j}$ scaled by its weight; the messages $\va{\alpha_{7j}}\,\vv{v_j}$ add up to $m_7$

$$m_i = \sum_{j \le i} \va{\alpha_{ij}}\, \vv{v_j}$$

The keys were used to compute the weights; they are not added into this message. All displayed numbers are rounded, while the calculation uses full precision.

m_bank = alpha @ V  # [7] @ [7, d_v] → [d_v]
V carries the information: $\va{\alpha_{ij}}\vv{v_j}$ is the message from $j$ to $i$.

Keys choose matches; values carry information. Their roles remain distinct even if some numbers happen to be equal.

Change only $W_V$’s “says finance” column. Keep the sentence, $W_Q$, $W_K$, and $W_O$ fixed.

W_V_alt = W_V.clone(); W_V_alt[:, 1] = 0
m_alt = alpha @ (E @ W_V_alt)  # same alpha, different information
Keys choose the weights. Values determine the weighted message. Next, $\vd{\Delta e_7}=m_7W_O$ maps that message back to the representation’s $d_{\text{model}}$ coordinates.

Keep in mind: the weights $\va{\alpha_{7j}}$ came from queries and keys alone, and the message $m_7$ came from values alone. Nothing about “bank” has changed yet. Turning $m_7$ into a change is the next section.
