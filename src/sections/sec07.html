Why we are here: search results carried a key and a value. Now every token in the sentence gets its own.

Every token becomes a searchable record

The search detour gave us three roles: a query that asks, a key that says when to answer, and a value that is the answer. Now every token gets a key and a value, computed from its own representation with two shared matrices, and the token gathering context gets a query from a third matrix.

Every coordinate has a name in this toy, so read the column headers before the numbers. Click a different query token and watch which rows stay open. Open a record and read its three rows. The sentence to remember: a query, a key and a value are three linear views of the same $\ve{e}$.

Bank is the receiver. It needs information from the words it has read.

Its query describes what to look for: $\vq{q_i}=\ve{e_i}W_Q$.

Each source publishes a key to match against: $\vk{k_j}=\ve{e_j}W_K$.

The same source publishes a value to send: $\vv{v_j}=\ve{e_j}W_V$.

The query and key choose where to read. The value supplies what is read.

Vectors are rows throughout this page. A representation has $d_{\text{model}}$ numbers; multiplying by a $d_{\text{model}}\times d_k$ projection produces $d_k$ numbers. Queries and keys share matching axes because a dot product compares corresponding coordinates. Values have their own axes, and may have a different width, because they are mixed rather than compared. The named coordinates are illustrative; the arithmetic is real.

Choose a receiver. Its input row is highlighted.

One record: what token $j$ publishes. Three rows, three sets of axis names

The key is a matching description. It is not the information added to bank.
A value is made from the embedding; it is not necessarily the embedding itself.

Keys: the query row sits above the key rows, under the same axis names

Values: what each open record sends if it is read

Three shared projections: $W_Q,W_K$ are $d_{\text{model}}\times d_k$; $W_V$ is $d_{\text{model}}\times d_v$

Look at: the same $W_Q$, $W_K$, $W_V$ act on every position. A row is an input axis of $\ve{e}$; a column is an output axis. Read each non-zero cell as “this axis feeds that axis”.

The same matrices are reused at every position.

q_i = e_i @ W_Q
k_j, v_j = e_j @ W_K, e_j @ W_V

Keep in mind: nothing has been compared or retrieved yet. Each token has only been given a query, a key and a value, all computed from its own $\ve{e}$ with matrices that every position shares.
