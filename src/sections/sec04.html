Why we are here: a fixed window mixes its slots the same way whatever words fill them, and it cuts off early tokens. So pool all earlier tokens instead.

Weighted pooling: where should weights come from?

Attention is a way to choose weights, so this section first shows what weights do. A pooled vector $c_i$ is a weighted sum of earlier representations, and the spreadsheets below make that sum visible: one row per token, one column per coordinate, a weight column on the left and the sum in the footer. Drag the position slider and watch the mean give every included row the same weight. Then move the raw-weight sliders for bank and watch the footer drift towards whichever row you favour. The sentence to remember: the weights decide what a token collects, and someone has to choose them.

Drop the window. Token $i$ can read every earlier representation $\ve{e_j}$, $j \le i$. The simplest way to combine them is an average:

$$c_i = \frac{1}{i}\sum_{j \le i} \ve{e_j}$$

Why not simply average all previous token representations? Try it on the short sequence.

Mean pooling: every earlier token gets the same weight $1/i$

Averaging treats every token equally. For bank, the word river matters far more than the. So let each token choose its weights:

$$c_i = \sum_{j \le i} \va{\alpha_{ij}}\, \ve{e_j}, \qquad \sum_{j} \va{\alpha_{ij}} = 1$$

This is weighted pooling. The weight $\va{\alpha_{ij}}$ says how much token $i$ takes from token $j$. Set the weights yourself.

Weighted pooling for token 7 (bank): choose a raw weight per token; they are normalised to sum to 1

You chose those weights by hand, because you know that bank wants river. A model cannot ask you, and a different token would want a different set of weights.

Where should the weights $\va{\alpha_{ij}}$ come from?

They should depend on what token $i$ currently needs and what information token $j$ contains. Both are functions of the representations themselves, $\ve{e_i}$ and $\ve{e_j}$. Attention is a way to build that function.

Keep in mind: the pooled vector is only as good as its weights, and the weights we want depend on the token that is asking and on the tokens that could answer. The next section hands that job to a search engine.
