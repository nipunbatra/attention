      01

      Why we are here: language tasks look different, yet each asks a network to turn text into useful predictions.

      What can a network do with text?

      A network can label a whole passage, label each token, translate between languages, shorten a notice, answer from a context, or continue a prompt. The output shape changes across these tasks. Generation looks especially open because several continuations can fit the same prefix. We can still give the network a precise job: assign one probability to every possible next token. Choosing or sampling one token turns that distribution into a continuation. This next-token view gives us a small problem that we can build from embeddings, an MLP, softmax, and cross-entropy.

      02

      Why we are here: a small character vocabulary lets us inspect every input, score, and probability.

      Generate a name

      We will train a network on Indian given names. Each letter is one token, and the boundary symbol marks both the empty space before a name and the stopping point after it. That gives the model a vocabulary of the boundary plus the alphabet. At each step it receives three character IDs and returns a probability for every possible next character. The displayed distribution for aab comes from the trained model bundled with this page. Its answer need not be certain. It only has to place useful probability on characters that often continue similar contexts.

      04

      Why we are here: characters are categorical symbols, while an MLP reads rows of numbers.

      Characters to numbers

      A one-hot vector identifies a character with one active coordinate. Different characters have zero dot product, so one-hot geometry offers no graded similarity. An embedding table replaces each long one-hot vector with a learned row of two numbers. Looking up a character means selecting its row; no averaging or calculation is needed. The first axis in this trained table was constrained so vowels are positive and consonants are negative. The second axis was free to move wherever the name-prediction loss found useful. These labels help us read the toy, but learned coordinates in larger models rarely have such simple names.

      05

      Why we are here: three embedding rows must become one fixed-width input without losing their positions.

      Concatenate the embeddings

      The lookup returns one embedding row for each character in the window. The MLP expects one row, so we place the three embeddings side by side. This makes a six-number vector because the window has three positions and each embedding has two coordinates. Each segment keeps its position: the first two numbers always describe the oldest character, and the last two describe the newest. Reversing the characters therefore changes the concatenation. Adding the same rows would erase their order because addition is commutative. The trained values below come directly from the embedding table you just inspected.

      06

      Why we are here: the six-number input must interact before the model can score the next character.

      Pass the vector through an MLP

      The concatenated row enters a one-hidden-layer MLP. The first matrix combines all six input coordinates into each hidden unit, adds a bias, and applies tanh. The second matrix combines the hidden activations into one logit for every vocabulary token. The diagram draws only a few hidden nodes, but the trained hidden row has the width reported beside it. The worksheets isolate one hidden unit and the logit for i. They show the same operations used for every other unit and output. Row vectors multiply matrices on the right throughout this series.

      07

      Why we are here: logits are unrestricted scores, so we need a normalized distribution over the vocabulary.

      27 scores to probabilities

      The output layer produces one logit for each vocabulary token. A logit can be positive or negative and does not yet act like a probability. Softmax exponentiates the scores and divides each result by their shared sum. Subtracting the largest logit before exponentiating keeps the calculation stable without changing the probabilities. The worksheet shows that stable form for aab. It keeps the five largest outcomes visible and groups the rest, while the denominator still uses every vocabulary entry. The final probabilities are positive and sum to one, so the model can sample from them.

      Top logits for a a b

      For every token $j$, $$p_j=\frac{\exp(z_j)}{\sum_{r\in\mathcal V}\exp(z_r)}.$$

      08

      Why we are here: training needs one number that says how well the distribution scored the observed target.

      The loss

      Each training row supplies a known next character. Cross-entropy keeps the probability assigned to that target and applies the negative logarithm. A confident correct prediction has a small loss. A confident wrong prediction gives the observed target very little probability and receives a large loss. The comparison below uses two simple probabilities from the lecture, while the interactive worksheet reads all six aabid rows from the trained model. Choosing another row changes its context, target probability, and loss together. Training later averages this signal across many rows and changes every parameter that contributed to the prediction.

      10

      Why we are here: a next-character distribution becomes a name only when we feed each choice back into the model.

      Sample, append, repeat

      Generation starts with three boundary tokens. The model predicts a distribution, then either chooses the largest probability or samples from the distribution. The chosen character is appended, the window shifts right, and the same model runs again. Sampling can produce different names because lower-probability characters remain available. Temperature changes how sharply the logits are converted to probabilities: lower values concentrate mass near the largest logits, while higher values spread it out. The visible window always shows the exact three tokens used for the displayed bars. Generation stops when the model chooses the boundary token.

      11

      Why we are here: training and generation run the same forward pass but obtain the next token in different ways.

      Training and generation

      During training, the data provides both the context and the observed next character. The model produces probabilities, cross-entropy scores the observed target, and the optimizer changes the parameters. Many windows can be processed in a batch because every window has the same shape. During generation, the next character is unknown. The model produces the same kind of distribution, then a rule chooses one character. That choice is appended to the context and becomes part of the next input. There is no target and no parameter update. The difference lies around the shared forward pass, not inside it.

      Training

      1. Known context and target
      2. Forward pass
      3. Cross-entropy loss
      4. Update the parameters
      5. Many fixed windows in a batch

      Generation

      1. Current context, target unknown
      2. Same forward pass
      3. Choose from the probabilities
      4. Append the choice
      5. Loop with the new window

      Keep in mind: training changes the model from observed targets, while generation holds the model fixed and extends the sequence.

      12

      Why we are here: the next-token objective stays the same even when one token stops meaning one character.

      What should a token be?

      Characters give a small vocabulary and can represent unfamiliar strings, but ordinary sentences become long. Whole words shorten the sequence and are easy to read, yet the vocabulary grows quickly and unseen words collapse to an unknown token. Subwords sit between these choices by reusing common pieces inside frequent and rare words. The widget applies three simple tokenizers to the same text and reports the resulting sequence length and the number of distinct displayed tokens. The subword merges are illustrative rather than a trained tokenizer. Later, attention will compare token pairs, so its cost depends strongly on the sequence length $T$.

      13

      Why we are here: replacing characters with words changes the vocabulary and data, but it does not change the prediction pipeline.

      Same model, word tokens

      A word-level model still turns token IDs into embeddings, combines a context, produces logits, and applies softmax. Only the tokenizer, vocabulary, and training text have changed. A prefix can support several reasonable continuations, so the output remains a distribution rather than a single rule. Training supplies one observed target at every position. The chain rule then expresses the probability of a complete sequence as a product of conditional next-token probabilities. This identity does not prescribe the network that represents the prefix. It tells us which probabilities the model must provide as the visible context grows.

      14

      Why we are here: concatenation fixes the number of context slots inside the first weight matrix.

      The context keeps growing

      The name model works because every input contains exactly three embeddings. Increasing the window changes the length of the concatenated row, so the first weight matrix must change shape. The sketch lets the window grow while keeping the embedding and hidden widths visible. This becomes costly for realistic widths: a hundred token slots, an embedding width of 256, and 1,024 hidden units require about 26 million first-layer weights. More importantly, the network still has a fixed number of slots. Natural-language prefixes keep growing, which leads to the design question for Part 2: how can a token read from a variable amount of earlier context?

      Pause and think

      Use these questions to reconstruct the model without following the page from top to bottom. Each answer connects one design choice to a concrete need. One-hot rows provide identity but no compact learned geometry. Concatenation preserves position. The output width matches the vocabulary because every token needs one logit. The negative logarithm rewards probability on the observed target and strongly penalizes near-zero probability. Changing the window changes the first matrix because its input width is $wd$. Generation can proceed only because training has taught the same forward pass to produce useful next-token distributions.

      Keep in mind: every component earns its place by preserving information, producing a distribution, or supplying a training signal.

      16

      Why we are here: one story should now connect token IDs, training loss, generated names, and the fixed-context limit.

      Three summaries

      Part 1 built a complete character language model. Three token IDs select embedding rows, concatenation preserves their positions, an MLP produces one logit per vocabulary token, and softmax turns those logits into probabilities. Cross-entropy compares the distribution with the observed next character and trains every learned table and matrix. During generation, the same model samples a character, appends it, shifts the window, and repeats. The method works, but the window width is fixed inside $W_1$. Part 2 keeps the next-token objective and changes how a token gathers information from its preceding context.

      Intuitive

      Use the last few characters to guess what character tends to come next.

      Operational

      Look up embeddings, concatenate the window, run the MLP, apply softmax, then sample or score the observed target.

      Mathematical

      $a_0=[\ve{e_1},\ldots,\ve{e_w}]$, $a_1=\tanh(a_0W_1+b_1)$, $p=\operatorname{softmax}(a_1W_2+b_2)$.

      The next-token objective stays. The representation of context must change.
